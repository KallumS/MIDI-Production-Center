## Goal

Build an MPC-style 16-pad sampler for REAPER that works on MIDI instead of
audio: load a MIDI sequence, chop it (transients / markers), map slices to pads,
time-stretch, and apply MIDI versions of filter, compressor, delay, EQ,
stutter and pitch correction. The owner's earlier Midular project was
available for ideas and code but is considered broken.

Inputs provided: the REAPER API function list (v7.79), the ReaScript overview
page, and the JSFX programming reference (zip).

## What was done

- Read the JSFX reference, the ReaScript API docs and the Midular repo
  (its `CLAUDE.md` list of JSFX pitfalls was especially useful).
- Chose JSFX over CLAP ([ADR 0001](../adr/0001-jsfx-not-clap.md)).
- Wrote the plug-in (`Effects/MIDI Production Center/`):
  - **core**: memory map, heapsort, 48 parameters, 64 pads, phrase handling,
    built-in demo groove, four chop modes (transient, grid, equal, markers)
    with optional held notes, per-slice forward/reverse play lists,
    `@serialize`.
  - **engine**: note scheduler with pair ownership, the six note effects,
    32 voices (one-shot / gate / loop hold / loop toggle, poly, choke groups,
    transpose, tape speed, stretch, fit-to-length, reverse, velocity
    sensitivity, output channel), stutter, swing, sync/original tempo, live
    sampling, gmem import, transport handling.
  - **ui**: scalable 1000×660 panel with header (SAMPLE / LOAD ITEM / PANIC),
    chop bar, phrase view (slice colours, playheads, marker editing, drag a
    slice onto a pad), 4×4 pads with banks A–D, and PAD / FX / SETUP pages.
- Wrote the loader scripts (`Scripts/MIDI Production Center/`): a shared
  library, a one-shot "load selected MIDI item" action, and a background loader
  that powers the in-plug-in LOAD ITEM button
  ([ADR 0002](../adr/0002-phrase-loading.md)).
- Ported Midular's EEL2 interpreter into `tests/`, added gmem, serialize and
  static compile-rule checks, and wrote the suites
  ([ADR 0007](../adr/0007-test-harness.md)).
- Wrote `README.md` (plain-language user guide), `CLAUDE.md` (developer
  notes) and `tests/README.md`.
- Follow-up (this commit): these docs - ADRs 0001-0007, this log, and
  `CLAUDE.md` updated to point at them.

## Decisions

Recorded as ADRs in [`docs/adr/`](../adr/README.md):

| ADR | Decision |
| --- | --- |
| 0001 | JSFX, not CLAP |
| 0002 | Phrases come in by live sampling or loader scripts over gmem, not files |
| 0003 | Phrase, markers and pads are saved inside the project |
| 0004 | Pitch = frequency axis, velocity = level; compressor has velocity / pitch / timing targets |
| 0005 | Each voice plays its own copy of its slice's play list |
| 0006 | One scheduler owns every note, so nothing can hang |
| 0007 | Verify with the EEL2 interpreter plus static compile checks |

Smaller calls made along the way:

- 64 pads (4 banks × 16), default trigger notes 36 upwards; pad 1 bottom-left
  like an MPC. REAPER names note 36 "C2", so labels use note numbers.
- Transient "hit" = notes starting within 0.04 beats, strength = summed
  velocity; the first hit always starts a slice.
- In Markers mode the phrase start only becomes a slice if notes come before
  the first marker, so "Edit as markers" keeps slice numbering.
- Pitch-correction ties round down.
- Default velocity sensitivity 50%; "Held notes" on by default (behaves like
  chopping audio).
- Live capture starts on the beat of the first note and is rounded up to whole
  bars.

### What was done

- Reviewed the code against the JSFX reference for anything that would behave
  differently in REAPER than in the harness (variable scoping, function
  locals, string functions). Nothing definite found, so rather than guess:
- **Status lights** in the header: AUDIO (is `@block` running), IN (MIDI
  arriving), OUT (notes leaving). Clicking or playing an **empty pad** now
  shows a message naming it, and clicking a pad while audio isn't running says
  so. These show where the signal stops.
- **Transfer to pads** ([ADR 0008](../adr/0008-pads-own-regions-transfer.md)):
  pads now hold their own region of the phrase instead of a slice number. The
  new TRANSFER TO PADS button fills the current bank (overflowing into the next
  banks) and empties the rest of that bank; it lights up when the chops have
  changed since the last transfer. New phrases are transferred to bank A
  automatically. Dropping a slice on a pad, the *Slice* control and the pad
  menu all write regions. The per-slice play-list pool was removed; voices
  build their lists from the region when triggered.
- Save format is now version 2; version-1 projects are migrated on load.
- **Bug found and fixed** by a new test: if REAPER runs `@init` before loading
  a project, the demo's queued auto-transfer would have overwritten the
  project's saved pads on the first block. Loading now cancels any queued
  transfer.
- README: transfer workflow, the lights, and a "No sound?" checklist.
  CLAUDE.md: current status, the new pad model, diagnostics, and that the pad
  record is now full.

### Smaller decisions

- Transfer starts at pad 1 of the bank on screen, not the selected pad.
- Transfer keeps every other pad setting (mode, transpose, notes...).
- The automatic transfer for a new phrase empties all 64 pads, since old
  regions refer to the old phrase.
- "Pad notes" still start at 36 per pad regardless of transfer.
